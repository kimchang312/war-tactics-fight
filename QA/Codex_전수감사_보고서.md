# WTF 잔존 버그 및 지휘관 시스템 전수 감사 보고서

- 감사 기준일: 2026-08-24
- Unity: 2022.3.25f1
- 최종 사양: `QA/지휘관 시트 (1).xlsx`의 `시트1`, `valueseet`
- QA 근거: `QA/WTF_QA_스테이지 프리셋.xlsx`, `QA/남은 작업 리스트 (1).xlsx`
- 원 요청의 `지휘관 시트 (1)(1).xlsx`는 저장소에 없었으며, 실제 존재하는 `지휘관 시트 (1).xlsx`를 최종 사양으로 사용했다.

## 1. 수정한 버그

### 1.1 지휘관 ID와 실행 디스패처 불일치

- 엑셀 항목: 스테이지 QA Fail 196/199/202/211/214/237/240, Next Event 205/226, 남은 작업 109·114행 및 지휘관 100~119·200~216 전 항목
- 원인: 엘리트는 내부 ID 1~20, 사양은 100~119, 보스는 이름 문자열과 프리셋 ID가 혼재했다. 전투 시작 디스패처는 엘리트 8종만 호출했고 보스 효과는 대부분 함수만 있거나 호출 경로 자체가 없었다.
- 수정 파일/함수: `CommanderCatalog.GetId`, `RogueLikeData.GetCurrentCommanderId`, `CommenderEffect.ApplyBattleStart`, `AbilityManager.ProcessCommenderEffect`
- 수정 내용: 엘리트 1~20을 100~119로 정규화하고 보스 이름을 200~216으로 매핑했다. 전투 프리셋에서 단일 정규화 ID를 얻어 공통 시작/전투 중 디스패처를 타도록 변경했다.
- 검증 방법: 실제 `Resources/PresetData/StagePresets.json`을 역직렬화하여 37개 사양 ID가 모두 적어도 한 프리셋과 연결되는지 테스트했다.
- 결과: EditMode `CommanderCatalog_MapsEverySpecificationId`, `StagePresetData_ConnectsEveryCommanderSpecificationId` 통과.

### 1.2 전투 이벤트·확률·중복 발동 공통 로직 누락

- 엑셀 항목: 아마록, 브루노, 시리온, 발레릭, 그론달, 오르테온, 아스모데우스, 아지라스, 멜세덱 및 커트·페리
- 원인: 보스 전투 중 이벤트 훅이 없었고, 턴 종료 중복 방지·주입 가능한 RNG·사망 횟수 기반 누적 상태가 없었다. 발레릭은 추가 선제 타격이 구현되지 않았으며 아지라스의 `*%` 곱연산 구분도 없었다.
- 수정 파일/함수: `AbilityManager.ShouldTriggerCommanderChance`, `ProcessCommanderTurnEnd`, `ApplyCommanderDeathEffects`, `CalculateAssassination`, `CalculateCharge`, `CalculateFirstStrike`; `StatBlock.GetStat`
- 수정 내용: RNG를 생성자에서 주입 가능하게 만들고 33%/50%/25% 경계값을 단일 함수로 처리했다. 턴당 1회 가드를 추가하고, 사망 이벤트·지원 사격·고정 피해·누적 상한·지연 턴·5턴/10턴 경계 전환을 실제 전투 단계에 연결했다. 아지라스만 사양의 곱연산 플래그를 사용한다.
- 검증 방법: 발동/미발동 RNG 경계, 동일 턴 두 번 호출, 턴 전후 수치, 사망 횟수, 장갑 0 최초 도달을 숫자로 비교했다.
- 결과: 관련 EditMode 테스트 9개와 PlayMode 멜세덱 테스트 1개 통과.

### 1.3 레논 처치 귀속 오류

- 엑셀 항목: 지휘관 102 레논
- 원인: 기존 코드는 전열 적이 전사이고 전열 플레이어가 죽었다는 간접 조건으로 처치자를 추정해, 다른 유닛의 피해에도 사기가 감소할 수 있었다.
- 수정 파일/함수: `AbilityManager.CallDamageText`, `TrackLennonWarriorDamage`, `CountLennonWarriorKills`, 공격/반격/지원/투창/암살 호출부
- 수정 내용: 실제 피해 원본 유닛을 전달하고 적 전사가 피해를 준 플레이어 대상만 기록한다. 그 대상이 이번 사망 목록에 들어간 경우에만 1명당 사기 -2를 적용한다.
- 검증 방법: 전사가 피해 준 사망자와 피해 주지 않은 사망자를 분리한 결정적 테스트.
- 결과: `Lennon_OnlyCreditsAPlayerDeathDamagedByAnEnemyWarrior` 통과.

### 1.4 장갑 하한과 지휘관 임시 능력치의 전투 간 누적

- 엑셀 항목: 아스모데우스, 아그마르, 남은 작업 117·118행
- 원인: 모든 장갑을 최소 1로 고정해 아스모데우스의 장갑 0 효과가 불가능했고, 지휘관 수치를 원본 필드에 직접 더해 전투 간 제거 출처가 불분명했다. 상세창은 계산된 값이 아닌 직접 필드를 읽었다.
- 수정 파일/함수: `RogueUnitDataBase.MinArmor`, `StatBlock.GetStat`, `StatBlock.RemoveModifiersBySourceAndId`, `UnitStateChange`, `CommenderEffect.RemoveCommanderEffect`
- 수정 내용: 일반 장갑 하한을 0으로 바꾸되 갈라진 방패(ID 32)만 최소 1을 유지한다. `SourceType.Commander` 출처의 modifier로 적용/제거하고 상세창도 계산값을 사용한다. 퍼센트 합연산과 곱연산을 구분했다.
- 검증 방법: 일반 장갑 1-5=0, 갈라진 방패 1-5=1, 전투 종료 제거 후 공격력 원복, 아지라스 100×1.2×1.5=180 비교.
- 결과: 관련 EditMode 테스트 4개 통과.

### 1.5 에레보스·라자루스·크롬홀드 시작 효과 누락

- 엑셀 항목: 스테이지 QA 211/214/237, 남은 작업 109행
- 원인: 함수가 호출되지 않았고, 에레보스는 `smokeScreen` 등 일부 기술과 임시 유격/상흔 효과를 제거하지 않았다.
- 수정 파일/함수: `CommenderEffect.ApplyBattleStart`, `ClearUnitSkills`
- 수정 내용: 양측 15개 기술 플래그와 임시 기술 효과를 제거한다. 라자루스는 적에게만 착취/흡혈, 크롬홀드는 적 창병/전사에 각각 투창/암살을 부여한다.
- 검증 방법: 플래그 및 효과 딕셔너리 직접 비교.
- 결과: `BattleStart_SkillAndStateEffectsMatchCommanderSheet` 통과.

### 1.6 벨페고르 탈취 조건·순서·배치 은폐 오류

- 엑셀 항목: 스테이지 QA 240, 남은 작업 114행
- 원인: 영웅/전설 조건을 혼동했고 전설도 후보에 포함했다. 탈취 유닛에 사양에 없는 30% 수치 증가를 적용하고 적 목록 끝에 넣었다. 배치 UI 은폐가 없었고 한국어 툴팁만 “영웅이 아닌”으로 잘못 생성되어 있었다.
- 수정 파일/함수: `CommenderEffect.ApplyBelphegor`, `EnemyInfoPanel`, `PlacePanel.CreateEnemyPrefabs`, `UnitUIPrefab.SetHidden`, `CommanderSkillData.GetSkillText`
- 수정 내용: `rarity != 4`만 후보로 삼아 양측 수치 적용 후 적 첫 번째로 이동하며 추가 수치 증가는 하지 않는다. 적 초상화/수치/에너지/클릭을 숨기고 숨김 이미지를 표시한다. 런타임 한국어 문구를 “전설이 아닌”으로 교정했다.
- 검증 방법: 전설+비전설 혼합 목록에서 후보/양측 리스트/첫 위치/공격력 불변과 툴팁 문자열을 비교했다.
- 결과: 관련 EditMode 테스트 2개 통과. 실제 RLmap 화면의 픽셀 수준 배치 확인은 미실행.

### 1.7 전투 진입 목록과 이벤트/챕터 2 동적 프리셋 연결

- 엑셀 항목: 남은 작업 35·51·57·110·111행
- 원인: 이벤트/챕터 2의 `presetID == -1` 또는 비어 있는 프리셋에서 전투 씬이 이미 생성된 `RogueLikeData.enemyUnits` 대신 빈 프리셋을 우선했다. 전투 전 유산이 아군 리스트를 재배치해도 `AutoBattleManager` 로컬 참조를 갱신하지 않아 용기의 버섯 등 구조 변경이 소실됐다.
- 수정 파일/함수: `AutoBattleManager.ProcessBeforeBattle`, 전투 초기화 및 commander 시작 순서
- 수정 내용: 동적/빈 프리셋은 런 데이터 적 목록으로 fallback하고, 양측 전투 전 처리 뒤 목록 참조를 새로 읽은 다음 지휘관 효과를 적용한다.
- 검증 방법: 데이터/호출 흐름 및 최종 Unity 컴파일. 완전한 이벤트→배치→전투 Scene 시퀀스는 자동 실행하지 못했으므로 통합 통과로 기록하지 않는다.
- 결과: root cause 수정, Scene 통합 검증 잔존.

### 1.8 기력 1 승리 후 잘못된 게임 오버

- 엑셀 항목: 남은 작업 101행
- 원인: 승리 직후 기력이 0이 된 마지막 유닛을 제거한 뒤 보상 전에 빈 로스터 패배 판정을 수행했다.
- 수정 파일/함수: `RewardManager.ShouldCheckEmptyRoster`, `RewardManager.Start`
- 수정 내용: 빈 로스터 선판정은 무승부/패배에만 수행하고 승리는 정상 보상 경로를 먼저 탄다.
- 검증 방법: result 0/1/2 파라미터 테스트.
- 결과: 3개 케이스 모두 통과.

### 1.9 수상한 부등다면체 null 예외

- 수정 파일/함수: `WarRelicDatabase.SuspiciousScalenePolyhedron`

- 검증 방법: 컴파일 및 호출 흐름 확인. 영웅 보유/미보유 실제 Scene 재현은 미실행.

## 5. 추가로 발견한 버그

### 5.1 Loot Bag 유산 중복 보상 및 약탈 미부여

- 원인: 양측 `ProcessTeamBeforeBattle`에서 금화 +20을 각각 지급해 총 +40이 됐고, 설명에 있는 무작위 2명 약탈 부여가 없었다.
- 수정: 플레이어 측에서만 +20, 약탈이 없는 후보 중 최대 2명에게 중복 없이 부여하고 전투 시작마다 `plunderGold`를 초기화한다.
- 테스트: 4명 중 기존 약탈 1명을 제외하고 정확히 2명만 부여됨을 검증.

### 5.2 Maniac 영웅의 선택 대상 무시

- 원인: 무작위로 뽑은 대상 목록을 계산한 뒤 실제 작열 적용은 `defenders[i]`에 해 선택 결과와 다른 유닛이 피해를 받았다.
- 수정: 선택된 대상 인스턴스와 실제 UI 인덱스를 사용한다.
- 검증: 컴파일 및 인덱스/대상 호출 흐름 확인. 해당 영웅 실제 Scene 실행은 미실행.

### 5.3 StagePreset `Value`와 유닛 가격 합 불일치

- 발견: `StagePresets.json`에서 24개 프리셋의 `Value`가 현재 유닛 가격 합과 다르며, 다수는 유닛 ID 6 가격 변경에 따른 +65 차이, 일부는 5/10 차이다.
- 판정: 데이터 QA 후보. `Value`가 표시용인지 편성 당시 스냅샷인지 최종 예산 검증값인지 사양이 없어 JSON을 직접 수정하지 않았다.
- 필요 자료: `Assets/Excels`의 프리셋 원본에서 Value 컬럼의 정의와 재생성 승인. 데이터 원칙에 따라 JSON 직접 편집은 금지했다.
